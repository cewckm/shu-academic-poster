# 字段与证据规则

脚本接受 UTF-8 JSON，所有值为字符串或 null。可以是扁平对象，也可以放在 `fields` 对象内。抽取器返回的其他字段只用于审核，生成器不会把它们当正文。

| 字段 | 用途 | 定稿要求 |
|---|---|---|
| title | 报告题目 | 必填；保留缩写拼写；排版时可去末尾句号 |
| speaker | 报告人姓名 | 必填；可从清楚的简介首句提取，复核推断 |
| affiliation | 报告人单位 | 必填；不要擅自换成简称或加入职称 |
| abstract | 摘要 | 必填；保留原文与段落（换行用 `\n`） |
| bio | 报告人简介 | 必填；不增加履历、论文数或荣誉 |
| date | 日期 | 必填，`YYYY-MM-DD`；脚本校验并自动计算星期 |
| start_time | 开始时间 | 必填，24小时 `HH:MM` |
| end_time | 结束时间 | 可省略；提供时须晚于开始时间 |
| location | 地点/线上会议 | 必填，如 `腾讯会议：123-456-789`；来自新文档 |
| inviter | 邀请人 | 可省略；缺省时页脚没有邀请人文字 |
| inviter_title | 邀请人职称 | 可省略；不可从旧活动继承 |
| inviter_email | 邀请人邮箱 | 可省略；不可猜测 |

当次明确用户指令 > 当次输入文档 > 用户批准的补充资料。样例只提供风格，不处于新活动事实来源链中。两份当次资料冲突时，展示冲突字段和来源，继续不依赖该字段的排版工作，等待用户解决冲突后定稿。

脚本不会替代理解：未识别标签、公式、浮动文本框、多栏顺序、图像中的信息，需要进一步检查原始 DOCX。`inferred_fields` 标注从正文推断的姓名或单位，`raw_event_times` 保留不完整日期；任何多候选值都要复核。输入如“11月6号下午4:00”只能确定月日和开始时间，不能确定年份或结束时间。

## 此次参考资料的已知差异

- 文档会议号：578-556-703；成功 PPTX 和 JPG：611-856-265。新文档生成测试保留文档号；只有明确要求复现成功版内容才使用后者。
- 文档时间只有“11月6号下午4：00”；成功版给出 2026-11-06、16:00–17:00。示例 JSON 中的年和结束时间明确来源于历史成功版，仅作本包验证。
- 文档没有邀请人资料；示例里用的是「某某、讲师、name@example.com」，仅作占位，禁止当作缺省值。
- 输入 DOCX、母版 PPTX 与参考图对同一个缩写的写法可能不一致（示例材料里就有一处字母顺序不同）。一律沿用**新输入原文**，不因图片或旧母版里拼写不同而改写。

## 一般调用示例

“读取 D:\wyj\skill\shu-academic-poster\SKILL.md，使用这份报告文档生成同款海报。日期为2026年12月8日，时间15:00–16:00，地点为腾讯会议123-456-789，邀请人信息如下……”。

若活动信息已完整写在 DOCX 中，不必在提示中重复。缺项时集中询问，已知内容先生成草稿。
